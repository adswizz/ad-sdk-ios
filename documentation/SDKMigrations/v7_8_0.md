# How to migrate to AdswizzSDK v7.8.0+

The **_AdswizzSDK_** v7.8.0 release contains architectural changes behind the scenes. In this guide you will find everything you need to know on how to update your application with the changes brought by **v7.8.0 and later**. For the latest changes, please visit the [Changelog](/iOS/CHANGELOG.md).

## What changed
The **_AdswizzSDK_** v7.8.0 has brought support for [AdswizzSDKPinpointAnalytics](/iOS/SDKPinpointAnalytics/AdswizzSDKPinpointAnalytics) framework. This required **_AdswizzSDK_** to separate the following public symbols into another dynamic framework named **_AdswizzSDKCore_**:
* Analytics
* AdLogger

Here is a breakdown of the implications from the latest changes.

### Prerequisites
* Xcode version bumped to 14+
* Swift version bumped to v5.6+ if the integration app uses Swift or Objective-C

### Dependencies
* Removed the _AWSCore_ dependency (**_AdswizzSDK.xcframework_**, by default, does not require anymore a dependency on the _Amazon's AWSCore_ external library)

As of **_AdswizzSDK v7.8.0_**, *Amazon’s AWSCore* is used to implement the AWS Pinpoint service needed by **_AdswizzSDKPinpointAnalytics_** framework.<br>
The _AWSCore_ dependency above is automatically added if you choose to integrate the **_AdswizzSDKPinpointAnalytics_** using Cocoapods. If you choose either the Carthage or the manual integration, you will have to provide it at link time.

## What you may need to do
Considering the changes above, your application _may_ need a few changes to support the update to **_AdswizzSDK_** v7.8.0. Here are the scenarios which are affected by the v7.8.0 release.

### Your application implemented the AnalyticsConnector protocol
If in your application you opted to implement the **_AnalyticsConnector_** interface for the purpose of capturing and using the [AdswizzSDK Analytics](/iOS/SDKiOS/AdswizzAnalytics), you will need to add a new import at the top of your source files that use the symbols defined within the `AASDKAnalytics` namespace (e.g: `AASDKAnalytics.Level`, `AnalyticsEvent`, `AnalyticsConnector` and so on).

```swift
import AdswizzSDK
import AdswizzSDKCore // -> new import needed

class MyAnalyticsConnector: AnalyticsConnector {
...
}
```

### You application uses and configures the AdLogger
If in your application you opted to use and configure the **_AdLogger_** provided by **_AdswizzSDK_** for the purpose of debugging, you will need to add a new import at the top of your source files that use the references any symbol related to the `AdLogger` component.

You will likely encounter this error when compiling your application updated with **_AdswizzSDK_** v7.8.0 and later:
<img src="/img/adLoggerCompileError.png" width="1000" />

Adding the correct `import` will solve the issue:
```swift
import AdswizzSDK
import AdswizzSDKCore // -> new import needed

extension AppDelegate: AdswizzSDKDelegate {
    func configureAdswizzSDK() {
      ......
      AdLogger.shared.level = .info
      AdLogger.shared.destination = self
      ......
    }
}
......
extension AppDelegate: AdLoggerDestination {
  func log(_ level: AdLogger.Level, functionName: String, fileName: String, lineNumber: Int, line: String) {
      //Pipe it to your logger
  }
}
```
