# How to migrate to AdswizzSDK v8.0.0+

The **_AdswizzSDK_** `v8.0.0` adds **Swift 6 support**. Its binary XCFrameworks are now compiled with Swift 6 strict concurrency checking enabled, which makes the SDK's public API explicit about the thread (actor) it expects to be used from. In this guide you will find everything you need to know on how to update your application with the changes brought by **v8.0.0 and later**. For the latest changes, please visit the [Changelog](/iOS/CHANGELOG.md).

## What changed

Prior to `v8.0.0`, the **_AdswizzSDK_** public API carried no concurrency annotations. Callers were *expected* to use it on the main thread, but nothing in the type system enforced it. Starting with `v8.0.0`, the SDK declares its isolation, and the compiler verifies it for you.

Here is a breakdown of the implications from the latest changes.

#### Main actor isolation

The classes you use to request and play ads are now annotated `@MainActor`:

| Symbol | Isolation in `v8.0.0` |
| --- | --- |
| `AdswizzSDK` (the shared singleton) | `@MainActor` |
| `AdRequestConnection`, `AdswizzAdRequest`, `AdswizzAdZone`, `AdswizzShimZone` and their builders | `@MainActor` |
| `AdManager` | `@MainActor` |
| `AdswizzAdStreamManager` / `AdStreamManager` | `@MainActor` |
| `AdswizzAdPodcastManager` / `AdPodcastManager` | `@MainActor` |
| `AdCompanionView`, `AdVideoView`, `TrackingPermissionController` | `@MainActor` (they are `UIKit` types) |
| `AdData`, `AdAsset` and the other ad data protocols | `@MainActor` members |
| `AdManagerSettings`, `AdStreamManagerSettings`, `AdPodcastManagerSettings` | not isolated |
| `AdLogger`, `AdEvent`, `Companion`, `VastExtension` | not isolated |

In practice this means: **anywhere you create, configure or call a method on one of these types, the calling code must itself be running on the main actor.**

#### Delegates and datasources

The manager delegates are `@objc` protocols, so they are **not** `@MainActor`. You implement them, and the **_AdswizzSDK_** invokes them on the main thread exactly as before. However, because their callbacks typically touch `AdData` members or your own UI state, the *conformance* usually has to be isolated — see [step 2](#2-isolate-your-sdk-delegate-conformances) below.

`InteractiveAdManagerDelegate` is the exception: it is already `@MainActor` in the SDK, so a `@MainActor` type satisfies it with no extra annotation.

#### Analytics interfaces and Objective-C exposure

The analytics interfaces in **_AdswizzSDKCore_** changed beyond isolation, and are **no longer exposed to Objective-C**:

| Symbol | Before `v8.0.0` | In `v8.0.0` |
| --- | --- | --- |
| `AnalyticsEvent` | `@objc` protocol | Swift-only, `: Sendable` |
| `AnalyticsEvent.params` / `.customParams` | `[String: Any]?` | `[String: any Sendable]?` |
| `AnalyticsCollecting` | `@objc`, `AnyObject` | Swift-only, `: AnyObject, Sendable` |
| `AnalyticsConnector` | `@objc` | Swift-only |
| `AnalyticsCollector` | `@objc` | Swift-only, `@MainActor` |
| `AnalyticsCustomData` | `@objc` | `@MainActor @objc` (still available to Objective-C) |
| `AdswizzSDK.add(connector:)` / `remove(connector:)` | `@objc` | Swift-only |

Analytics events are delivered **off the main actor**, which the SDK now declares rather than merely documenting.

#### Prerequisites

* **_AdswizzSDK_** `v8.0.0` binary frameworks are compiled with **Xcode 26.4.1** and **Swift 6**.
* Build your application with **Xcode 26.4.1 or newer**, so that your toolchain understands the concurrency annotations exported in the SDK's module interface. Building with the **latest available Xcode** is always recommended.
* Your application can remain on the **Swift 5 language mode**. Adopting the Swift 6 language mode is optional — see [Your application adopts the Swift 6 language mode](#your-application-adopts-the-swift-6-language-mode).

## What you need to do

Although we always recommend updating **_AdswizzSDK_** to the latest version, the migration to `v8.0.0` is mechanical and in most applications consists of the two steps below. Note that both are compile-time annotations only: they add no runtime overhead when your code already runs on the main thread, which is the supported usage.

#### 1. Make the type that owns your managers `@MainActor`

This single change resolves the majority of the errors, because every SDK call inside the type is then known to run on the main actor. An `ObservableObject` backing your SwiftUI views, or a `UIViewController`, is a natural fit.

```swift
import AdswizzSDK

@MainActor                                  // <- add this
final class AdsViewModel: ObservableObject {
    private var adManager: (any AdManager)?
    private var connection: AdRequestConnection?

    @Published var isPlaying = false

    func skip() {
        adManager?.skipAd()                 // ✅ now allowed — we are on the main actor
    }
}
```

Without it you will see errors such as:

> Call to main actor-isolated instance method `'skipAd()'` in a synchronous nonisolated context<br>
> Call to main actor-isolated initializer `'init(for:)'` cannot be called from outside of the actor<br>
> Main actor-isolated property `'delegate'` can not be mutated from a nonisolated context

#### 2. Isolate your SDK delegate conformances

Mark the conformance itself `@MainActor` so the callbacks may touch main-actor state:

```swift
extension AdsViewModel: @MainActor AdManagerDelegate {   // <- @MainActor on the conformance
    func adManager(_ adManager: any AdManager, didReceiveAdEvent event: any AdEvent) {
        switch event.event {
        case .preparingForPlay:
            hasCompanion = event.ad?.hasCompanion ?? false   // ✅ AdData members are @MainActor
        case .readyForPlay:
            adManager.play()                                 // ✅ @MainActor method
        case .didStartPlaying:
            isPlaying = true                                 // ✅ main-actor property
        default:
            break
        }
    }

    func adManager(_ adManager: any AdManager, didReceiveAd ad: (any AdData)?, error: any Error) { /* … */ }
}
```

Apply the same annotation to every **_AdswizzSDK_** delegate and datasource your type conforms to:

| Protocol | Isolate the conformance |
| --- | --- |
| `AdManagerDelegate` | Yes |
| `AdManagerDatasource` | Yes |
| `AdManagerInterstitialEventDatasource` | Yes |
| `AdStreamManagerDelegate` | Yes |
| `AdPodcastManagerDelegate` | Yes |
| `AdCompanionViewDelegate`, `AdVideoViewDelegate` | No — see [Your application wraps AdCompanionView](#your-application-wraps-adcompanionview-in-a-uiviewrepresentable) |
| `InteractiveAdManagerDelegate` | No — already `@MainActor` in the SDK |

Without it you will see errors such as:

> Main actor-isolated property `'adTitle'`/`'hasCompanion'`/`'selectedCompanion'` can not be referenced from a nonisolated context

#### Client Side Insertion

`AdRequestConnection`, `AdManager` and the request and zone builders are all `@MainActor`. Own them from a `@MainActor` type and isolate the `AdManagerDelegate` conformance. Nothing else about the integration changes. For the functional details, see [Client Side Insertion](/iOS/SDKiOS/ClientSideInsertion).

```swift
@MainActor
final class ClientSideModel: ObservableObject {
    private var adManager: (any AdManager)?
    private var connection: AdRequestConnection?

    func requestAds() async {
        do {
            let zone = try AdswizzAdZone.Builder().with(zoneId: zoneId).build()
            let request = try AdswizzAdRequest.Builder()
                .with(server: adServer)
                .with(zone: zone)
                .build()                                        // ✅ the builders are @MainActor

            let connection = try AdRequestConnection(for: request)
            self.connection = connection

            let adManager = try await connection.requestAds()    // ✅
            self.adManager = adManager
            adManager.delegate = self
            adManager.adManagerSettings = AdManagerSettings()
            adManager.prepare()
        } catch {
            // handle the invalid request
        }
    }
}
```

> The completion-handler form of `requestAds(completion:)` keeps working unchanged. Its callback is delivered on the main actor, so `self` remains accessible inside it. The `async` variant shown above is often tidier inside a `@MainActor` type.

#### Server Side Insertion

`AdswizzAdStreamManager` and its builder are `@MainActor`. Isolate the `AdStreamManagerDelegate` conformance, and isolate the `AdManagerDelegate` conformance you use for the ad break the delegate hands you. For the functional details, see [Server Side Insertion](/iOS/SDKiOS/ServerSideInsertion).

```swift
@MainActor
final class ServerSideModel: ObservableObject {
    private var streamManager: AdswizzAdStreamManager?
    private var adBreakManager: (any AdManager)?

    func start(streamURL: URL) throws {
        streamManager = try AdswizzAdStreamManager.Builder()
            .with(adServer: adServer)
            .with(httpProtocol: .https)
            .with(companionZones: companionZones)
            .build()

        streamManager?.delegate = self
        streamManager?.adStreamManagerSettings = AdStreamManagerSettings()
        try streamManager?.play(with: streamURL)       // ✅ @MainActor
    }
}

extension ServerSideModel: @MainActor AdStreamManagerDelegate {
    func adStreamManager(_ manager: AdStreamManager, adBreakStarted adBreak: any AdManager) {
        adBreakManager = adBreak
        adBreak.delegate = self
        adBreak.interactiveDelegate = self             // ✅ InteractiveAdManagerDelegate is already @MainActor
    }
    // … the remaining AdStreamManagerDelegate methods …
}

extension ServerSideModel: @MainActor AdManagerDelegate { /* … */ }
```

#### Podcasts

Podcasts follow the same shape, using `AdswizzAdPodcastManager` and an isolated `AdPodcastManagerDelegate` conformance. For the functional details, see [Podcasts](/iOS/SDKiOS/Podcasts).

```swift
extension PodcastModel: @MainActor AdPodcastManagerDelegate {
    func adPodcastManager(_ manager: AdPodcastManager, didReceive adBreak: any AdManager) {
        adBreakManager = adBreak
        adBreak.delegate = self
        adBreak.interactiveDelegate = self
    }
    // … the remaining AdPodcastManagerDelegate methods …
}
```

> Two `AdswizzAdPodcastManager` methods became asynchronous starting with `v8.0.0`: `startDownloadPodcast(with:to:)` and `stopDownloadPodcast(at:)` are now `async throws`, so they must be awaited from an asynchronous context. `removePodcast(at:)` is unchanged.

#### HLS Interstitials

The controller or monitor you pass to `AdManagerSettings.adInterstitialEventMonitor`, together with the `AdManager`s driving your interstitial events, should be owned by a `@MainActor` type — a `UIViewController` already is. Isolate the `AdManagerDelegate` and `AdManagerInterstitialEventDatasource` conformances. For the functional details, see [HLS Interstitials](/iOS/SDKiOS/HLSInterstitials).

```swift
import AVFoundation
import AdswizzSDK

// Building against recent SDKs, add `@retroactive` to this conformance to silence the
// "extension declares a conformance of imported type to imported protocol" warning.
extension AVPlayerInterstitialEventMonitor: @retroactive AdInterstitialEventMonitor {}

@MainActor
final class HLSInterstitialsController: NSObject {
    private let primaryPlayer: AVPlayer
    private var monitor: AVPlayerInterstitialEventMonitor?
    private var controller: AVPlayerInterstitialEventController?
    private var adManager: (any AdManager)?

    private func configure(_ adManager: any AdManager) {
        let settings = AdManagerSettings()
        settings.adInterstitialEventMonitor = monitor   // `weak` — keep your own strong reference
        adManager.adManagerSettings = settings
        adManager.delegate = self
        adManager.prepare()                             // ✅ @MainActor
        self.adManager = adManager
    }
}

extension HLSInterstitialsController: @MainActor AdManagerInterstitialEventDatasource {
    func adManager(_ adManager: any AdManager, interstitialMediaFileURL ad: any AdData) -> URL? {
        // `AdData` members are @MainActor, which is why this conformance is isolated.
        ad.asset.mediaUrl.flatMap(URL.init(string:))
    }
}
```

## What you may need to do

Here are some changes that _may_ be needed to support the update to **_AdswizzSDK_** `v8.0.0`.

#### Your application uses SwiftUI

Most likely **nothing**. Apple annotates `App`, `Scene`, `View` and `UIViewRepresentable` with `@MainActor` at the protocol level, so *every* member of a conforming type — not only `body` — is already main-actor isolated. Initializing the SDK in your `App.init()`, constructing an `AdCompanionView` inside `makeUIView(context:)` and reading your `@Published` state all keep compiling untouched.

The breakage appears in your **own plain types**: the `ObservableObject` view models, `NSObject` controllers and helper classes that hold a manager. Those get no automatic isolation, which is what [step 1](#1-make-the-type-that-owns-your-managers-mainactor) addresses.

#### Your application initializes the SDK outside a main-actor context

`AdswizzSDK.shared` is `@MainActor`. From a SwiftUI `App.init()` or an `AppDelegate`, no change is needed. Otherwise, wrap the call:

```swift
Task { @MainActor in
    // Build the configuration inside the main-actor context: `AdswizzSDKConfig` is not `Sendable`,
    // so creating it outside and capturing it here is a data-race error in the Swift 6 language mode.
    let config = AdswizzSDKConfig(playerId: playerId, installationId: installationId)
    try? await AdswizzSDK.shared.initialize(with: config)   // async variant of initialize()
}
```

#### Your application wraps AdCompanionView in a UIViewRepresentable

`AdCompanionViewDelegate` is an `@objc` protocol, and the `Coordinator` that implements it is reached from nonisolated code. Keep the `Coordinator` **nonisolated** and give it its own stored callbacks, rather than isolating its conformance or having it read state from the surrounding struct:

```swift
struct CompanionView: UIViewRepresentable {
    private let onEvent: (String) -> Void

    func makeUIView(context: Context) -> AdCompanionView {
        let view = AdCompanionView()        // makeUIView is already main-actor isolated
        view.delegate = context.coordinator
        return view
    }

    func updateUIView(_ uiView: AdCompanionView, context: Context) {
        uiView.activateIfNeeded()
    }

    func makeCoordinator() -> Coordinator { Coordinator(onEvent: onEvent) }

    final class Coordinator: NSObject, AdCompanionViewDelegate {
        private let onEvent: (String) -> Void
        init(onEvent: @escaping (String) -> Void) { self.onEvent = onEvent }

        func adCompanionViewDidDisplay(_ adCompanionView: AdCompanionView) {
            onEvent("didDisplay")
        }
        // … remaining delegate methods forward to the stored closures …
    }
}
```

> A closure formed on the main actor and stored as a plain `(String) -> Void` loses its isolation, so the compiler will not verify what the `Coordinator` calls through it. This is safe because **_AdswizzSDK_** invokes these delegates on the main thread. If you would rather have the guarantee enforced, hop explicitly inside the callback.

The same applies to `AdVideoViewDelegate`. More details in [Companion Banner](/iOS/SDKiOS/CompanionBanner) and [Video ads](/iOS/SDKiOS/VideoAds).

#### Your application implements the podcast seek callback

The completion block of `adPodcastManagerPlayer(_:shouldSeekTo:completion:)` is now `@Sendable`. Update the signature, and keep calling the block once your player finishes seeking:

```swift
func adPodcastManagerPlayer(_ adPodcastManager: AdPodcastManager,
                            shouldSeekTo time: TimeInterval,
                            completion: @escaping @Sendable () -> Void) {
    externalPlayer.seek(to: time) { completion() }
}
```

#### Your application updates main-actor state from an AVFoundation callback

Some `AVFoundation` callbacks — `AVPlayer.addPeriodicTimeObserver(forInterval:queue:using:)` among them — take a `@Sendable` block, even when you pass `queue: .main`. Writing to main-actor state directly from one produces:

> Main actor-isolated property `'playhead'` can not be mutated from a Sendable closure

Hop explicitly:

```swift
player.addPeriodicTimeObserver(forInterval: interval, queue: .main) { [weak self] time in
    let seconds = time.seconds
    Task { @MainActor in self?.playhead = seconds }
}
```

#### Your application adopts the Swift 6 language mode

Setting your target's Swift Language Version to **6** additionally enforces full data-race safety, so `Sendable` violations become errors rather than warnings. If you have completed the two steps above, this step is usually uneventful. What may still surface:

* Values shared as globals must be `Sendable`. A common case is a stateless logger you pipe SDK logs into via `AdLoggerDestination`, which can simply be declared `final … Sendable`:

```swift
final class MyLogger: Sendable, AdLoggerDestination {
    func log(_ level: AdLogger.Level, functionName: String, fileName: String, lineNumber: Int, line: String) {
        // pipe into your own logging
    }
}
```

* Passing a `@MainActor` method as a bare function reference (for instance into a SwiftUI `Button(action:)`) can confuse the compiler. Wrap it in an explicit closure instead:

```swift
Button(action: { model.isPlaying ? model.stop() : model.requestAds() }) { Text("Go") }
```

#### Your application implements AnalyticsConnector or AnalyticsEvent

Beyond dropping `@objc` (see [Analytics interfaces and Objective-C exposure](#analytics-interfaces-and-objective-c-exposure)), two things change how you write a connector.

**Events are delivered off the main actor, and your connector must be safe to use from any isolation domain.** `AnalyticsCollecting` now refines `Sendable`. Keep your connector free of unsynchronised mutable state, and hop explicitly if a callback needs main-actor state:

```swift
import AdswizzSDK
import AdswizzSDKCore

final class MyConnector: AnalyticsConnector {
    func log(_ event: any AnalyticsEvent, _ timestamp: Date) {
        let id = event.id                              // read Sendable values here…
        Task { @MainActor in updateMyUI(with: id) }     // …then hop for main-actor state
    }

    func send(forced: Bool) { /* flush */ }
}

// Registering the connector is a main-actor call:
AdswizzSDK.shared.add(connector: MyConnector())
```

**Event parameter values must be `Sendable`.** `params` and `customParams` changed from `[String: Any]?` to `[String: any Sendable]?`, so placing an arbitrary object in them no longer compiles. Put values that are already `Sendable` (`String`, numbers, `Bool`) in the dictionary, or convert first.

If you implement `AnalyticsCustomData`, its own `params` property is **unchanged** (`[String: Any]?`) — the SDK snapshots it for you through the new `sendableParams` helper. The conformance does now have to be main-actor isolated:

```swift
@MainActor
final class MyCustomData: AnalyticsCustomData {
    var params: [String: Any]? { ["tier": "premium", "count": 3] }
}
```

#### Your application supplies its own player

`MediaPlayerState` is now `@MainActor` and refines `Sendable`. Because the protocol is main-actor isolated, the practical change is to isolate your player type so that its state is only read from the main actor — which is where the **_AdswizzSDK_** already expected to read it:

```swift
@MainActor
final class MyPlayer: NSObject, MediaPlayerState {
    var currentPlayhead: TimeInterval { /* … */ }
    var playerStatus: MediaPlayerStatus { /* … */ }
    // … remaining MediaPlayerState members …
}
```

Keep updating the player's state on the main thread, as before. `MediaPlayerCapability` and `MediaPlayerCapability.State` are now `Sendable` and can be passed across isolation domains freely. More details in [External Player](/iOS/SDKiOS/ExternalPlayer).

#### Your application is written in Objective-C

The `@MainActor` annotations by themselves do not produce new Objective-C build errors: the annotated APIs keep their `@objc`/`AASDK…` names, and Objective-C has no compile-time actor checking. The runtime requirement is unchanged: **call the SDK on the main thread.**

The **analytics** interfaces are the exception. The following are no longer present in the generated Objective-C headers:

* `AASDKAnalyticsEvent`
* `AASDKAnalyticsCollecting`
* `AASDKAnalyticsCollector`
* `AASDKAnalyticsConnector`
* `-[AASDKAdswizzSDK addWithConnector:]` and `-[AASDKAdswizzSDK removeWithConnector:]`

If your Objective-C target implements or registers an analytics connector, it will no longer compile. Bridge through a small Swift class that implements the connector and exposes an `@objc` entry point to your Objective-C code:

```swift
@objc(MyAnalyticsBridge)
public final class MyAnalyticsBridge: NSObject, AnalyticsConnector {

    public func log(_ event: any AnalyticsEvent, _ timestamp: Date) {
        // forward to your Objective-C analytics layer
    }

    public func send(forced: Bool) {}

    @objc @MainActor public static func register() {
        AdswizzSDK.shared.add(connector: MyAnalyticsBridge())
    }
}
```

`AASDKAnalyticsCustomData` is still available to Objective-C, so custom event parameters need no bridging.

## Troubleshooting

| Compiler message | Fix |
| --- | --- |
| *Call to main actor-isolated instance method `'prepare()'`/`'play()'`/`'pause()'`/`'skipAd()'`/`'reset()'`/`'cancel()'` in a synchronous nonisolated context* | Mark the enclosing type `@MainActor`. See [step 1](#1-make-the-type-that-owns-your-managers-mainactor). |
| *Call to main actor-isolated initializer `'init(for:)'`* / *…method `'build()'`/`'with(server:)'` cannot be called from outside of the actor* | Same as above — the builders, `AdRequestConnection`, `AdswizzAdStreamManager` and `AdswizzAdPodcastManager` are `@MainActor`. |
| *Main actor-isolated property `'delegate'`/`'adManagerSettings'`/`'ads'`/`'url'` can not be mutated (or accessed) from a nonisolated context* | Same as above; the access must run on the main actor. |
| *Main actor-isolated property `'adTitle'`/`'hasCompanion'`/`'selectedCompanion'` can not be referenced from a nonisolated context* (inside a delegate method) | Isolate the conformance: `extension Model: @MainActor AdManagerDelegate`. See [step 2](#2-isolate-your-sdk-delegate-conformances). |
| *Expression is 'async' but is not marked with 'await'* | You are calling `requestAds()`, the `async` overload. Add `await`, or use the completion-handler overload. |
| *Main actor-isolated property … can not be mutated from a Sendable closure* | You are inside a `@Sendable` callback. See [Your application updates main-actor state from an AVFoundation callback](#your-application-updates-main-actor-state-from-an-avfoundation-callback). |
| *Extension declares a conformance of imported type `'AVPlayerInterstitialEventMonitor'` to imported protocol `'AdInterstitialEventMonitor'`* | Add `@retroactive` to the conformance. See [HLS Interstitials](#hls-interstitials). |
| *Sending `'config'` risks causing data races* (Swift 6 language mode) | `AdswizzSDKConfig` is not `Sendable`. Create it inside the main-actor context rather than capturing it from outside. See [Your application initializes the SDK outside a main-actor context](#your-application-initializes-the-sdk-outside-a-main-actor-context). |
| *`let '…'` is not concurrency-safe because non-`'Sendable'` type … may have shared mutable state* (Swift 6 language mode) | Make the shared type `Sendable` (or an `actor`). See [Your application adopts the Swift 6 language mode](#your-application-adopts-the-swift-6-language-mode). |
| *Cannot find protocol declaration for `'AASDKAnalyticsConnector'`* (Objective-C) | The analytics interfaces are no longer exposed to Objective-C. Bridge through a Swift class. See [Your application is written in Objective-C](#your-application-is-written-in-objective-c). |
| *Type of expression is ambiguous* / *argument type … does not conform to `'Sendable'`* when building `params` or `customParams` | Those dictionaries are now `[String: any Sendable]?`. Use `Sendable` values, or convert first. See [Your application implements AnalyticsConnector or AnalyticsEvent](#your-application-implements-analyticsconnector-or-analyticsevent). |
| *`'startDownloadPodcast(with:to:)'` is only available in an asynchronous context* | The podcast download methods are now `async throws`. Await them. See [Podcasts](#podcasts). |
| *Failed to produce diagnostic for expression; please submit a bug report* around a `Button(action:)`/callback | You likely passed a `@MainActor` method as a bare function reference. Wrap it in a closure. |

## Checklist

- [ ] Build with Xcode 26.4.1+ (latest recommended).
- [ ] Annotate the view models and controllers that own `AdManager`, `AdRequestConnection`, `AdswizzAdStreamManager` or `AdswizzAdPodcastManager` with `@MainActor`.
- [ ] Isolate your `AdManagerDelegate`, `AdManagerDatasource`, `AdManagerInterstitialEventDatasource`, `AdStreamManagerDelegate` and `AdPodcastManagerDelegate` conformances with `@MainActor`. Leave `InteractiveAdManagerDelegate` as it is.
- [ ] Keep `@objc` delegate `Coordinator`s nonisolated and give them their own callbacks; create `@MainActor` SDK views inside `makeUIView`.
- [ ] Update the podcast seek callback signature to the `@Sendable` completion block, and `await` the podcast download methods.
- [ ] If you implement `AnalyticsConnector`/`AnalyticsEvent`: make the connector safe to use off the main actor, and use `Sendable` values in `params`/`customParams`.
- [ ] If you supply your own player: isolate your `MediaPlayerState` type to the main actor.
- [ ] Objective-C targets registering an analytics connector: add a Swift bridge.
- [ ] Hop explicitly out of `@Sendable` `AVFoundation` callbacks that touch main-actor state.
- [ ] Rebuild and confirm there are no remaining actor or `Sendable` diagnostics.

For the functional integration details of each scenario, see [Client Side Insertion](/iOS/SDKiOS/ClientSideInsertion), [Server Side Insertion](/iOS/SDKiOS/ServerSideInsertion), [Podcasts](/iOS/SDKiOS/Podcasts), [HLS Interstitials](/iOS/SDKiOS/HLSInterstitials) and the [Sample Projects](/iOS/SDKiOS/SampleProjects).
